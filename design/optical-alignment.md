# 光学对齐备忘（Optical Alignment）

> 测度上的对齐 ≠ 眼睛里的对齐。实现时优先让**视觉重心**咬合，而不是 bounding box 的数学中心重合。  
> 资料来源：Gestalt / UI 光学补偿类教程（韩语），已转写为合域落地页可执行规则。

---

## 一、核心原则

| 现象 | 原因 | 做法 |
|------|------|------|
| 同宽圆比方「小」 | 圆角切掉四角，视觉面积少 | 圆要比同尺寸方框 **略大**（约 +10%～15% 直径）才显得等量 |
| 尖头/鱼尾条比矩形条「短」 | 尖端视觉质量轻 | 尖端 **超出** 对齐线 2%～5%（如 1000px → 1020px） |
| 圆环包住文字仍「偏」 | 环是曲线容器，文是矩形块 | 分别补偿环心 Y/X 与文案 `translate`，勿只调一个 |
| 深色底块里的白字「缩进」 | 对齐了盒子边，没对齐字 | **对齐字形**，盒子可向左/outdent 探出栏外 |
| 浅色底块里的字「断行」 | 对齐了灰底左缘 | **对齐上下段文字**，浅底可吃进 margin |
| 图标在圆里「偏左/偏右」 | 用了 SVG 外接矩形居中 | 按 **视觉质心/尖端分布** 微调；Play 类 **略向尖端方向推** |
| 画布居中块「下坠」 | 几何 50% 居中 | 单块元素 **略上移**；双体（环+文）用分体常量 |
| 十字/加号图标横线显粗 | 横竖同 stroke | 横线 **减 0.5～1px** 或 90% 粗细 |
| 400×400 反而不像正方形 | 竖向敏感 | 方形资产可 **宽 +0.5%～1%** |

## 二、文字垂直：Cap height / x-height

按钮、标题、单行标签：

1. **全大写 / 无 descender**（OK、Cancel）→ 以 **cap height** 为上下留白基准。  
2. **混排、有 descender**（Play、Sync、g/y/p）→ 以 **x-height 主体** 为视觉中心；descender **允许悬在底边距里**，不要把整字 bbox 几何居中（会显得字偏上）。  
3. **中文大标题 + 正文 + 按钮**（开屏 Hero）→ 视觉重心通常在 **大标题 cap 区与副标题之间**，高于整块几何中心 → 文案块宜 **略下移**，或环心 **略低于 50%**。

---

## 三、文字水平：非对称 padding

箭头形 CTA（Send ▶）：

- 数学居中：左右 padding 相等 → 字显得靠右（尖端侧空）。  
- 光学平衡：左 padding **小于** 右 padding（例：135px / 155px），字 **略向左移**。

合域启示：`进入工作台` 若在异形/毛玻璃容器内，左右 padding 不必对称。

## 四、形状与对齐线

```
几何对齐（错）          光学对齐（对）
┌─────────┐            ┌─────────┐
│ 矩形条  │            │ 矩形条  │
└─────────┘            └─────────┘
┌────────┐             ┌──────────┐
│ 条  ╲  │             │ 条    ╲──│← 尖端超出对齐线
└────────┘             └──────────┘
     ↑ 对齐线              ↑ 对齐线
```

- **圆角按钮** 右缘：可略 **内收**，避免深色块显得「顶出栅格」。  
- **尖角按钮** 右缘：尖端应 **略超出** 与输入框对齐的竖线。

## 五、图标在圆形容器内

纸飞机类非对称图标：

- ❌ 外接正方形中心 = 圆心  
- ✅ 让 **尖端 + 两翼** 到圆边的距离感均衡 → 图标常需向 **尖端反方向** 偏移

合域：流程时间轴圆节点、智库气泡尾巴，都按 **形状** 而非 **canvas 框** 调位置。

### 5.1 Play 三角：「外接圆」法（资料补充）

三角形、箭头等 **一侧平、一侧尖** 的图标：

```
❌ 三角 bbox 中心 = 按钮中心     ✅ 先给三角画外接圆，圆心 = 按钮中心
   ┌──▶┐  看起来偏左               ┌──( ◁ )──┐  视觉均衡
   └───┘                           └─────────┘
```

步骤：形状 → 外接圆 → 圆对齐背景 → 必要时再 **整体向尖端反方向** 微移。

合域：流程节点里的 Lucide 图标若在圆形容器内，优先 **圆形容器居中**，图标 `translate` 微调，而不是图标 bbox 居中。

## 六、圆本身：几何圆 vs 修正圆（Squircle）

人眼常觉得 **3 号几何圆** 略「缺」，**4 号修正圆** 更自然——对角方向略「鼓出」，比同宽高几何圆 **稍大**。

| 类型 | 特征 | 观感 |
|------|------|------|
| 几何圆 | 每点到圆心等距 | 有时偏「瘦」「硬」 |
| 修正圆 / 超椭圆 | 对角 overshoot，曲率连续 | 更「圆」、更柔 |

**字体里的 overshoot**：Futura / Circe 的字母 **o**，即使号称几何，四角也会 **超出** 外接圆——否则与 H、E 并列时显得偏小。这叫 **overshoot**，与 UI 里「圆要比方框大一点」同一逻辑。

合域已有实践：`speech-bubble-layout.ts` 的 `squarishMap(n, exp=3.4)` 即 **超椭圆近似**（Lamé 曲线族），让智库气泡轮廓比纯 `border-radius` 更柔，与粒子云边缘一致。

---

## 七、圆角：几何弧 vs 曲率连续（iOS / Squircle）

标准 CSS `border-radius` = 直线 **突然** 接四分之一圆，切点处曲率 **跳变**，眼会察觉「拐一下」。

| 方式 | 曲率 | 实现 |
|------|------|------|
| 几何圆角 | 0 → 固定半径，不连续 | `border-radius` |
| 曲率连续 / 超椭圆 | 渐变加速，切点不可察 | Lamé 曲线、SVG path、mask、`squircle` |

Lamé 曲线（Marc Edwards / iOS 7+ 图标思路）：

```
|x/a|^n + |y/b|^n = 1    （n 约 4～5 时接近 iOS 图标感）
```

**代价**：纯 CSS 难一步到位，常需 SVG、`clip-path`、PNG mask 或设计稿导出。

合域当前策略：

- Hero 按钮：`rounded-sm`（克制，偏编辑/杂志，非 App 图标）
- 毛玻璃卡片：小圆角 + 高 blur，靠 **材质** 而非 squircle 撑质感
- 智库气泡粒子：**超椭圆采样** 已做；若以后要实色气泡 UI，可复用同一 `squarishMap`

## 八、本章「要记住的三件事」（资料原文归纳）

1. **尖角/三角** 挨近方形时：略放大或 **overshoot**，才与方形成视觉平衡。  
2. **按钮文字** 与背景：用 **cap height** 对齐，别用整行 bbox。  
3. **三角/箭头图标** 在方钮里：用 **外接圆定心**，再微调——不要 bbox 居中。

## 九、速查卡 01～04（本批资料）

### 01 · 播放三角的重心

| | 数学居中 | 视觉补偿 |
|---|---------|---------|
| 现象 | 左竖边「重」，整体 **偏左** | 三角 **略向右** 移过圆心 |
| 原因 | bbox 中心 ≠ 质量中心 | 左宽右尖，需用 **重心** 对齐 |

```
     ◁ 偏左              (  ◁ )  均衡
   ───┼───              ───┼───
     圆心                  圆心（三角略右）
```

与 §5.1 外接圆法 **叠加**：先外接圆定心，再向 **尖端方向** 轻推 2%～8% 容器宽。

### 02 · 圆相对方的 Overshoot

方与圆 **同像素高** 时，圆显小 → 圆顶/底应 **略超出** 水平参考线（overshoot）。

```
─── 参考线（方顶/底） ───
┌───┐     ╭───╮
│   │     │   │  ← 同高：圆显矮
└───┘     ╰───╯

─── 参考线 ───
┌───┐    ╭─────╮
│   │    │     │  ← 圆略高：视觉等高
└───┘    ╰─────╯
   ↑ overshoot
```

合域：`RING_INNER_RADIUS_RATIO` 放大即此逻辑——环要给文字 **视觉等高** 的留白，不是数学内切。

### 03 · 画布上的视觉中心

单块元素（卡片、图标、圆角方）放在 **几何正中央** 时，常觉 **往下坠**。

- ❌ `top: 50%` + `translateY(-50%)` 精确居中  
- ✅ 整体 **略上移**（如 `-52%`、`-mt-1`、`-0.3vh`）

**注意**：开屏是 **环 + 文案** 双体对齐，不能机械套用「整体上移」——见 §十一 分体常量。单章卡片、弹窗、居中 Logo 适用本条。

### 04 · 横竖线错觉（＋ 号 / 十字）

同像素粗细时，**横线看起来比竖线粗** → 画十字时 **横线略细**。

| 元素 | 建议 |
|------|------|
| `+` / 关闭图标 | 横 stroke 比竖 **少 0.5～1px** 或 90% 粗细 |
| 表格分隔 | 水平 `border` 可略浅/略细于垂直 |
| 流程连线 `↓` | 竖线可略粗于横连接器（与十字相反，因竖为主轴） |

## 十、正方形错觉 & 字体补偿

### 10.1 哪个更像「正方形」？

402×398 往往比 400×400 **更像** 正方形——人眼对 **竖向距离更敏感**，略 **加宽** 才觉方。

| 用途 | 启示 |
|------|------|
| 方形缩略图 / 图标底 | 可 **宽 +0.5%～1%** |
| 全屏 Hero 块 | 宽屏下内容区略扁时，垂直动效/环可 **略上移** 平衡 |

### 10.2 字体里的光学（与 UI 同源）

- **O**：比几何圆 **略宽**，四角 overshoot，与 H/E 并列才 **等高**。  
- **H**：竖画比横画 **略粗**，才 **等重**。

→ 衬线标题（Noto Serif SC）+ 无衬线正文混排时，**不要** 用同一 `font-weight` 期望视觉等重。

## 十二、调参 checklist（开屏 / 新组件）

1. 先 **几何居中** 作起点（`50%` + `translate(-50%,-50%)`）。  
2. 截图看 **上/下/左/右留白** 哪边「更重」。  
3. 只动 **1～2 个轴**，每次 0.2vh～0.5vh 或 0.5%～2% 内容宽。  
4. 圆与文 **反向微调** 往往比同向更有效。  
5. 滚动过渡章节时，光学偏移须 **随 `shiftT` 淡出**，避免分屏章被带偏。  
6. **单块居中** → 试 `-52%` 上移；**圆对方** → 试 overshoot；**十字图标** → 横线减细。

## 十四、何时上 Squircle（决策树）

```
需要 App 图标级、硬件感圆角？
  ├─ 是 → SVG / clip-path / squircle 库（见第七节公式）
  └─ 否 → 品牌偏杂志/私行？
           ├─ 是 → 小 radius + 毛玻璃/衬线（合域 v1 现状）
           └─ 否 → 标准 border-radius 即可
```

粒子/Canvas 轮廓：优先 **参数曲线采样**（如现有 `squarishMap`），比 CSS 圆角更贴「视觉圆」。
