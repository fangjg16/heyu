# 投资主题与赛道分类

根据标的的经济实质进行分类，不根据交易包装、项目代号或单个关键词猜测。

## 必读资料

每次分类都读取：

- `references/taxonomy.md`：唯一有效的一级、二级分类白名单。
- `references/decision-rules.md`：边界规则、证据优先级和典型冲突示例。

不得新增、改写、合并或拆分白名单标签。若没有合理匹配，输出“分类体系未覆盖”，并提出扩表建议；不得为了给出结果而强行归类。

## 工作流程

1. 提取项目名称和可得内容。优先识别：实际产品或服务、付费客户、收入来源、核心资产、价值链环节、主要业务地区和投资标的范围。
2. 用一句话重述经济实质：`标的通过[核心活动/资产]，向[客户]提供[产品/服务]，主要通过[收入来源]变现。`
3. 区分投资对象与交易形式。股权投资、控股收购、Buy-to-Build、基金、SPV、REITs 申报或创业阶段本身都不是行业分类依据。
4. 读取分类白名单和边界规则，先选择一级主题，再在该主题内选择二级赛道。二级必须从白名单逐字选取。
5. 检查相邻主题。至少比较一个最容易混淆的候选，并说明为何不选。
6. 按证据充分程度标注置信度和结论状态。信息不足时仍给出最佳暂定结论，不阻断用户流程。

## 主次分类

- 默认只给一个主分类。
- 只有当不同业务线各自形成实质性收入、利润、资产价值或明确投资命题时，才给最多两个次分类。
- 不得因为客户横跨多个行业、产品有多个功能或描述中出现多个行业词就给多标签。
- 若无法判断哪条业务线是经济重心，将主分类标为“暂定”，列出决定分类所需的最少信息。
- 若投资对象是资产组合或集团，优先按本次实际投资范围分类，而非集团全部业务。

## 置信度与状态

- `高`：项目内容明确说明核心业务、客户和变现方式，且没有实质性边界冲突。
- `中`：业务实质基本清楚，但缺少收入构成、资产属性或业务占比等关键佐证。
- `低`：主要依赖项目名称、宣传语或行业关键词推断；仅有名称时置信度不得高于低。
- `已确认`：存在直接且一致的项目内容证据。
- `暂定`：已有最佳匹配，但信息不足或存在接近候选。
- `分类体系未覆盖`：白名单中不存在合理的一级与二级组合。

不得虚构收入占比、客户类型、业务模式或项目内容。外部搜索只能补充事实，不能覆盖用户提供的项目边界；用户未要求研究时，分类本身不要求联网。

## 输出格式

先给结论，再给依据。默认使用以下紧凑格式：

```markdown
**主分类**：{一级主题板块} → {二级可投子赛道/业务环节}
**状态 / 置信度**：{已确认|暂定|分类体系未覆盖} / {高|中|低}
**经济实质**：{一句话}
**判断依据**：{2–4 条来自输入的事实；信息少时明确说明}
**边界说明**：{最接近的其他候选及不选原因}
**待确认**：{仅列会改变分类的 0–3 个问题；没有则写“无”}
```

存在次分类时追加：

```markdown
**次分类**：
- {一级} → {二级}：{为何构成独立实质业务}
```

分类体系未覆盖时，主分类写：

```markdown
**主分类**：分类体系未覆盖
**建议扩表方向**：{建议的一级/二级标签，但明确其尚非白名单}
```

当调用方需要机器可读结果、批量归类或写入 Heyu 项目文件时，同时返回：

```json
{
  "taxonomy_version": "2026-08-12",
  "project_name": "",
  "classification_status": "confirmed | provisional | uncovered",
  "primary": {
    "theme": "",
    "subsector": ""
  },
  "secondary": [],
  "confidence": "high | medium | low",
  "economic_essence": "",
  "evidence": [],
  "boundary_note": "",
  "open_questions": []
}
```

`uncovered` 时将 `primary.theme` 和 `primary.subsector` 设为 `null`。不要把建议扩表标签写进白名单字段。

## 与 Heyu 三个插件协作

- CapitalLens：可把结果用于项目入库、行业尽调路由、可比项目分组和组合标签；不得由行业分类直接推出投资结论。
- Buy-to-Build：按收购标的的经营实质分类；不得把 owner-operator、平台收购、roll-up 或并购整合作为主题赛道。
- Startup：按拟建立的主营业务分类；商业模式仍未确定时输出暂定结果。纯技术产品若与白名单业务环节没有合理对应，标记分类体系未覆盖。
- 跨插件交接：保持相同的 `taxonomy_version`、主分类和次分类；只有新证据改变经济实质时才重分类，并说明变更原因。
