# 投资主题与赛道分类

根据标的的经济实质进行分类，不根据交易包装、项目代号或单个关键词猜测。

## 必读资料

每次分类都读取：

- `references/taxonomy.md`：唯一有效的一级、二级分类白名单。
- `references/decision-rules.md`：边界规则、证据优先级和典型冲突示例。

不得新增、改写、合并或拆分白名单标签。输出时逐字使用 `taxonomy.md` 中的一级和二级名称。

资料有限或没有完全对应标签时，仍须选择最接近的白名单组合，匹配类型为 `closest` 并降低置信度。只有输入完全没有产品、服务、行业、客户、资产或业务词，或所有具体标签在核心交付物和价值链环节上均为零匹配时，才使用 `现代服务业 → 综合商业运营与其他企业服务`。不得输出“暂定”“暂无法归类”“分类体系未覆盖”，不得将主分类字段留空，也不得把建议标签写入正式字段。

## 工作流程

1. 提取项目名称和可得内容。优先识别：实际产品或服务、付费客户、收入来源、核心资产、价值链环节、主要业务地区和投资标的范围。
2. 用一句话重述经济实质：`标的通过[核心活动/资产]，向[客户]提供[产品/服务]，主要通过[收入来源]变现。`
3. 区分投资对象与交易形式。股权投资、控股收购、Buy-to-Build、基金、SPV、REITs 申报或创业阶段本身都不是行业分类依据。
4. 读取分类白名单和边界规则，先选择一级主题，再在该主题内选择二级赛道。二级必须从白名单逐字选取。
5. 检查相邻主题。至少比较一个最容易混淆的候选，并说明为何不选。
6. 按证据充分程度标注置信度。信息不足时仍给出最接近的白名单分类，不阻断用户流程。

## 主次分类

- 默认只给一个主分类。
- 只有当不同业务线各自形成实质性收入、利润、资产价值或明确投资命题时，才给最多两个次分类。
- 不得因为客户横跨多个行业、产品有多个功能或描述中出现多个行业词就给多标签。
- 若无法判断哪条业务线是经济重心，按决策规则中的平局顺序选择主分类，其余实质业务可列为次分类。
- 若投资对象是资产组合或集团，优先按本次实际投资范围分类，而非集团全部业务。

## 置信度与状态

- `高`：项目内容明确说明核心业务、客户和变现方式，且没有实质性边界冲突。
- `中`：业务实质基本清楚，但缺少收入构成、资产属性或业务占比等关键佐证。
- `低`：主要依赖项目名称、宣传语或行业关键词推断；仅有名称时置信度不得高于低。
- `已确认`：存在直接且一致的项目内容证据。
- `closest`：没有完全对应标签，已按交付物、计价方式、核心资产和价值链环节选择最接近的正式标签。

不得虚构收入占比、客户类型、业务模式或项目内容。外部搜索只能补充事实，不能覆盖用户提供的项目边界；用户未要求研究时，分类本身不要求联网。

状态只使用 `已确认` 或省略；置信度使用 `高` / `中` / `低`。不要输出“暂定”或“分类体系未覆盖”。

## 输出格式

先给结论，再给依据。默认使用以下紧凑格式：

```markdown
**主分类**：{一级主题板块} → {二级可投子赛道/业务环节}
**状态 / 置信度**：{已确认} / {高|中|低}
**经济实质**：{一句话}
**判断依据**：{2–4 条来自输入的事实；信息少时明确说明}
**边界说明**：{最接近的其他候选及不选原因}
**待确认**：{仅列会改变分类的 0–3 个问题；没有则写“无”}
```

存在次分类时追加：

```markdown
**次分类**：
- {一级} → {二级}：{为何构成独立实质业务}
```

零匹配兜底时，主分类写：

```markdown
**主分类**：现代服务业 → 综合商业运营与其他企业服务
**匹配类型**：closest
```

当调用方需要机器可读结果、批量归类或写入 Heyu 项目文件时，同时返回：

```json
{
  "taxonomy_version": "2026-08-26-r2",
  "project_name": "",
  "classification_status": "confirmed | closest",
  "primary": {
    "theme": "",
    "subsector": ""
  },
  "secondary": [],
  "confidence": "high | medium | low",
  "economic_essence": "",
  "evidence": [],
  "boundary_note": "",
  "open_questions": []
}
```

`closest` 时仍填写白名单内的 `primary.theme` 和 `primary.subsector`。零匹配时使用 `现代服务业` / `综合商业运营与其他企业服务`。不要把非白名单建议写进正式字段。

## 与 Heyu 三个插件协作

- CapitalLens：可把结果用于项目入库、行业尽调路由、可比项目分组和组合标签；不得由行业分类直接推出投资结论。
- Buy-to-Build：按收购标的的经营实质分类；不得把 owner-operator、平台收购、roll-up 或并购整合作为主题赛道。
- Startup：按拟建立的主营业务分类；商业模式仍未确定时给出 closest 结果并降低置信度。纯技术产品按自身产品与收费模式归入软件、云计算或对应垂直标签，不等同于客户所经营的业务。
- 跨插件交接：保持相同的 `taxonomy_version`、主分类和次分类；只有新证据改变经济实质时才重分类，并说明变更原因。
