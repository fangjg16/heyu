# 正式业务尽调

Use in Phase 3A. Produce or update `03-diligence/business-diligence.md` using every required formal section. Separate facts, management claims, inference, assumptions, and gaps. Do not omit a material section because evidence is absent: label it `未核验`, state the investment consequence, and issue a specific evidence request. Send financial validation needs to financial diligence and external market tests to industry diligence. If baseline screening reveals a material identity, ownership, affiliation, adverse-record, disclosure-integrity, or related-party signal, run Phase 3B using `dd-background-check.md`.

## 1. 目标与原则

业务尽调要从“生意”的角度还原标的，而不是复述 BP。目标是同时回答：标的当前真实经营什么，以及它凭什么持续完成交易和放大规模。

坚持以下原则：

1. 先定义业务，再评价好坏。先写清客户、任务、交付物、产品形态和收费方式。
2. 区分经营事实、管理层规划和投资人推断。远期平台叙事不得与当期主营业务混写。
3. 以过程证据代替自述。合同、订单、产品演示、交付、验收、发票、回款、续约、工单和访谈应能相互印证。
4. 核心能力必须解释为可观察、可重复、可归因的产品能力或交易能力，不能只列专利、履历、客户名单或技术名词。
5. 比例原则只改变深度和样本量，不允许隐藏对投资判断重要的章节。

## 2. 启动前定义

先固定：分析实体和期间、业务所处阶段、重大业务单元、现有与拟开展业务、目标交易、决策问题、证据截止日，以及需要行业或财务工作流复核的主张。

用一句话定义真实业务：

> 标的向【客户/使用者】提供【具体功能或任务结果】，通过【软件/硬件/服务/内容/数据/组合产品】交付，并以【定价与付费方式】取得收入。

若不能形成不含宣传词的一句话定义，业务仍未被理解。

## 3. 正式分析程序

### 3.1 真实业务与边界

- 建立“当前主营 / 当前非核心 / 邻近延伸 / 远期愿景 / 已停止”业务地图。
- 按收入、订单、资源投入、客户采用、行业关系和转型可行性判断核心与非核心，不照抄公司分类。
- 解释多产品、多场景、平台模式、软硬一体或定制项目之间的真实关系，识别是否只是围绕特定大客户的定制集成。
- 对收入尚未形成的项目，用开发进度、可用产品、试点、验收和付费承诺界定“正在经营”与“计划经营”。

最低证据：产品清单、合同或订单清单、收入分产品明细、组织和资源配置、产品演示、客户/用户访谈。

### 3.2 业务演进与战略一致性

按时间线记录公司设立、产品迭代、客户变化、渠道变化、重大合作、融资、团队变化和业务转向。对每个拐点回答：为何发生、投入何种资源、结果如何、暴露了何种能力或约束。

检验当前战略是否延续已证明的能力，还是要求团队在产品、客户、渠道、交付和资本强度上同时跃迁。把尚无证据的跃迁列为承保条件（underwriting condition，即只有当某条件达成，才会投入、成交或继续推进；否则就不做或用更保守的假设），而非成长性事实。

### 3.3 产品与技术

先写产品体系，再写具体产品：

- 分类与关系：产品族、系列、版本、模块、在售/研发/停用状态及收入贡献；
- 产品定义：解决什么任务，交付什么具体“东西”或能力；
- 功能、结构、工作原理：关键部件或模块如何协作；
- 技术原理与核心指标：用可比较、可测试的指标说明效果、成本、稳定性、安全和可扩展性；
- 研发与知识产权：人员、流程、版本、投入、权属、第三方依赖和可替代性；
- 应用案例：从输入、配置、使用、输出、验收到商业结果还原真实场景。

产品截图、专利数量、开源组件清单和概念架构只能证明存在，不能单独证明成熟度、差异化或壁垒。

### 3.4 商业模式与交易闭环

逐项还原并检查逻辑一致性：

| 模块 | 必答问题 | 典型证据 |
|---|---|---|
| 客户与使用者 | 谁决策、谁采购、谁使用、谁受益；行业/区域/规模/集中度 | 客户主数据、访谈、合同 |
| 销售与交易 | 直销/渠道；标准/定制；价格、折扣、账期、验收、退款 | 合同、报价、订单、审批 |
| 获客 | 线索来源、销售周期、转化、渠道激励、CAC | CRM、渠道协议、漏斗 |
| 采购与供应 | 买什么、向谁买、议价、单一来源、替代周期 | 采购单、供应商访谈、账期 |
| 生产与交付 | 产能、利用率、排期、实施、验收、质量和返工 | 工单、产能表、验收单、SLA |
| 研发 | 需求来源、路线图、版本节奏、研发效率、外包依赖 | 代码/版本记录、项目台账 |
| 服务与续约 | 上线、支持、活跃、留存、续费、扩单和流失 | 使用日志、工单、续约记录 |
| 盈利与资本 | 单位收入、直接成本、贡献毛利、营运资金和资本开支 | 财务明细、成本归集、现金周期 |

建立逻辑一致性测试。例如：面向低客单消费者却高度定制；标准产品却长期依赖实施人天；高毛利叙事却需要重大硬件或算力投入；渠道增长却没有渠道激励成本。偏离可能是创新，也可能是遗漏，必须解释并取证。

### 3.5 运营、组织与关键依赖

- 分析关键流程、产能、质量、服务水平、信息系统和扩张瓶颈。
- 量化客户、供应商、渠道、技术平台、数据、创始人和关键员工集中度。
- 对员工看时点与期间变化：人数、职能、薪酬、入离职、关键岗位空缺、外包和兼职投入。
- 对团队评价使用履历核验、共同项目、行为证据和第三方访谈；不把创始人自述改写成事实。
- 识别老板依赖、关键人替代周期、代码/数据/客户关系可转移性，以及灾备和安全响应能力。

### 3.6 核心能力与竞争力归因

核心能力分为：

- 产品能力：持续创造客户可感知价值的技术、产品、数据、交付、质量或成本能力；
- 交易能力：持续找到客户、促成交易、履约、回款和续约的渠道、供应链、品牌、服务或组织能力。

先判断标的是产品型、交易型，还是处于中间形态。对应用开发、系统集成、软件外包、贸易和渠道型企业，原创技术可能不是壁垒；行业知识、交付、成本控制、供应链或客户覆盖可能更重要。

每项核心能力必须回答：客户价值、形成机制、可观察指标、独立证据、复制成本、替代方案、可持续期、关键依赖、失效条件。没有这些要素时只能列为“待证能力”。

### 3.7 主张测试、反证与抽样

- 对收入、客户、产品成熟度、性能、交付能力、留存、产能和壁垒建立主张表。
- 对每项重大主张主动设计反证：若不成立，会观察到什么；现有证据是否也支持另一种解释。
- 交易抽样覆盖新增、续约、最大客户、异常折扣、期末集中、退款/退货、关联方和流失客户；样本量按风险和总体规模确定，并披露覆盖率与局限。
- 客户、供应商和员工访谈必须记录选择方法，避免只访问管理层安排的正面样本。

## 4. 跨流勾稽

- 发给财务尽调：订单—交付—验收—发票—收入—回款链、毛利和单位经济、客户与供应商集中、研发/交付成本、外包及关联方。
- 发给行业尽调：需求真实性、替代方案、市场边界、价格带、竞争者、客户采用摩擦、行业增长和监管。
- 接收财务反馈：收入或毛利异常、客户集中、资本化、回款、现金消耗是否推翻业务模型。
- 接收行业反馈：需求、市场结构、价格或技术替代是否推翻核心能力或扩张假设。

按 `dd-principles.md` 更新共同主张矩阵和失效状态。
