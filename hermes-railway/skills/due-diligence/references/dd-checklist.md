# Diligence Request List

Use in Phase 2. Maintain `03-diligence/diligence-request-list.md`. Every request must state the claim or decision it tests, expected evidence, workstream, priority, owner, status, and consequence if unresolved. Never label the request list a diligence report.

Each item contains:

- request ID and workstream;
- claim or decision tested;
- requested evidence and sample/period definition;
- purpose and expected analytical use;
- priority and consequence if unresolved;
- owner, due date, status, and response/source IDs;
- follow-up or closure basis.

Prioritize decision-changing evidence over completeness. A request can be closed by adequate evidence, shown irrelevant, or accepted as an attributable exception; silence is not closure. This artifact scopes work and never substitutes for a business, industry, or financial diligence conclusion.
